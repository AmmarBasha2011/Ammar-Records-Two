# Ammar-Records-Two

> **Quran & Nasheed Content Pipeline** — Automated vertical Shorts generation for YouTube with webhook-based posting.

---

## 📖 Overview

This repository is a self-contained content pipeline that:
1. **Stores** audio segments (Quran ayahs + nasheed verses) in numbered folders
2. **Metadata** per folder via `iden.json` (type, name, segments, timestamps)
3. **Builds** vertical 9:16 Shorts (1080×1920) from random segment ranges
4. **Posts** automatically via webhook (n8n/sokt.io) — no YouTube OAuth needed
5. **Uploads** video to GitHub Release (`latest-short`) for downstream download

### Channel Goal
- **YPP (YouTube Partner Program):** 4,000 qualified watch hours + 1,000 subscribers
- **Strategy:** Long-form content (≥1 min) counts toward watch hours; Shorts help with subs
- **Current:** 244 qualified watch hours (3 years)

## 🔄 Workflows

### 1. Video Autopost (`video-autopost.yml`)
- **Trigger:** Every 30 minutes (cron) + manual
- **Steps:**
  1. Pick random 1-6 segments from available nasheeds
  2. Concatenate audio segments with ffmpeg
  3. Pick random background image
  4. Render 9:16 Short (1080×1920, H.264 + AAC)
  5. Upload video to GitHub Release (`latest-short`)
  6. Send metadata + video_url to webhook (n8n/sokt.io)
- **Output:** Short video + webhook payload

### 2. Video Cleanup (`video-cleanup.yml`)
- **Trigger:** After Video Autopost completes
- **Steps:** Wait 5 minutes → remove `latest-short` release asset

### 3. Video Re-upload (`video-reupload.yml`)
- **Trigger:** Daily at 18:15 UTC + manual
- **Steps:** Pick best-performing Short → re-upload for reach

## 🚀 Adding a New Nasheed

1. **Prepare audio file** (mp3/wav)
2. **Transcribe with Groq Whisper large-v3** → get segments with timestamps
3. **Cut audio** using `tools/quran_split.py` or manual ffmpeg:
   ```bash
   ffmpeg -ss START -to END -i input.wav -c:a libmp3lame -q:a 2 output.mp3
   ```
4. **Create folder** (e.g., `117/`)
5. **Create `iden.json`** with segments metadata
6. **Update `available.json`** and `links.json`
7. **Commit and push**

## 📊 Audio Processing Pipeline

```
Audio File (mp3/wav)
    ↓
Groq Whisper large-v3 (STT)
    ↓
Segments with timestamps (start, end, text)
    ↓
Filter empty/no-speech (no_speech_prob > 0.3)
    ↓
Cut audio per segment (ffmpeg)
    ↓
Save as 000.mp3, 001.mp3, ... in numbered folder
    ↓
Create iden.json with metadata
    ↓
Update available.json + links.json
    ↓
Commit + Push
    ↓
Workflow picks random segments → builds Short → webhook
```

## 📝 Notes

- **Audio files** are stored directly in the repo (not LFS) for small files (<50MB each)
- **Large files** (>50MB) should use Git LFS
- **Segments** are numbered 000-NNN (0-indexed)
- **Nasheeds** start at 115 (after 114 Quran surahs)
- **Empty/no-speech segments** are filtered (no_speech_prob > 0.3)
- **Whisper STT** segments by silence, not by poetic lines — multiple lines may be in one segment
